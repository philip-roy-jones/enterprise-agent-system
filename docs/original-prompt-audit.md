# Original prototype requirements

This audit covers the bounded demonstration in `original-prompt.txt`, including the requested Windows deployment and OpenRouter provider. It does not treat arbitrary new workflow generation, production adoption, or an unlimited number of worker VMs as requirements for the original demonstration.

**The bounded prototype is implemented and demonstrated.** This audit distinguishes the runnable prototype from production readiness, generic legacy-app support, and arbitrary workflow generation. The evidence below covers the original requirements plus the requested separate Windows deployment. New generated proposals still require their own developer decision; an unapproved proposal is never a release.

## Final acceptance evidence

- **Executable contracts and budgets:** typed inputs and outputs for every registered operation and reusable public adapter operation. Per-operation deadlines reach browser/HTTP waits and action fences; retries require fresh invocations and Strict approvals. Failed browser refreshes cannot relabel historical state as fresh evidence. In-flight external operations are reconciled rather than abandoned by killing a thread.
- **Conversation:** staff guidance reaches the assistant, invalidates queued proposals, and never counts as approval. Approved questions wait durably for deduplicated answers. A live OpenRouter/Windows run asked its question, consumed the simulated staff answer, reported the requested purchase-order total, and made no business mutation: 6 model calls, 24,567 tokens. See [live conversation evidence](evidence/live-staff-conversation.json).
- **Evidence-derived improvements:** analysis inspects graph/library source, groups failures, and joins staff decisions with executed actions, bound observations, field results, and verified saves. The generated v3 candidate passed 127 isolated tests, including learned-label jobs on different records/layouts, and GitHub checks. [Its draft review artifact](https://github.com/philip-roy-jones/enterprise-agent-system/pull/2) remains unapproved and undeployed. See [derived improvement evidence](evidence/derived-improvement.json).
- **Human-reviewed release:** the earlier v2 candidate was approved by the project developer, passed exact-commit CI, and handled a different native invoice without fallback. Its v1 teaching episode remains pinned; v1 is retained for rollback. See [release evidence](evidence/reviewed-release.json).
- **Four mutation outcomes:** not attempted, uncertain, confirmed succeeded, and confirmed failed are distinct. An explicit application rejection records failure; absence of a result or a timeout remains uncertain. A rejected Save can be retried only through an individually approved assistance tool. The rejection fixture exercises the browser app; native adapters retain uncertainty when they lack authoritative rejection evidence.
- **Evaluation:** staff assess completed operations; reported incorrect actions, assessed actions, and unassessed actions are separate counts. Reporting an error revokes episode acceptance until resolved. Approval requests and corrections are separate. Model usage, elapsed time, fallback frequency, completion rates, and proposal regression failures are recorded. Newly failed/cancelled runs retain terminal timing; older runs without timing are counted explicitly rather than guessed.
- **Native and frontend rollout:** the backend and Windows harness were updated while idle. The final native check saved INV-1042 in 21.93 seconds using mouse/keyboard, with zero fallback/model calls and the application API disabled. Deployed source hashes and interactive session were checked. Chromium verified assessment submission, an incremented live metric, both active sidebar tabs, and no JavaScript errors. See [final rollout evidence](evidence/final-windows-validation.json).
- **Checks:** 139 tests passed in [acceptance CI](https://github.com/philip-roy-jones/enterprise-agent-system/actions/runs/34559108561), including terminal timing, browser console, and fresh-observation regressions; native accounting smoke checks and both Windows builds passed. A final five-second backend shutdown bound was separately verified with an open event stream: the isolated process exited after cleanup in 5.19 seconds.

## Reviewed release demonstration

The human project developer approved [PR #1](https://github.com/philip-roy-jones/enterprise-agent-system/pull/1), commit `cac88dea82cdd5aa05f78113012fa1d75385ff67`, after 95 isolated tests and GitHub checks passed. The prototype released version v2 while idle and retained v1 for rollback. A different invoice completed on Windows with the changed label, the application API disabled, zero fallback/model calls, and a verified saved draft. The accepted teaching episode remains pinned to v1. See [reviewed release evidence](evidence/reviewed-release.json).

The original release check used Windows accessibility actions. The separately diagnosed keyboard-focus race was then fixed and verified with native mouse/keyboard jobs. Earlier failed checks remain in the evidence. Staff acceptance was simulated; developer release approval was human.

## Deliberate prototype limits

The worker has one configured organization and an explicit role allowlist. Staff authentication still uses a shared workspace token: there is no employee membership directory, per-person department ACL, production tenant isolation, or independently hardened automation sandbox. A role is not an operating-system security boundary. Multiple authorized roles may share a worker sequentially; additional real security boundaries need independently enforced credentials and isolation.

The improvement generator implements one bounded reusable change. General workflow-code generation, full recording of unmediated human demonstrations, arbitrary graph deployment, and generic vision-only control remain future work. Those should not be implied by the original teaching demonstration or by the README's statement of motivation.
